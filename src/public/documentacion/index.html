Middleware Zabbix & Smart OLT

Manual técnico detallado del integrador. Este middleware recibe alertas de conectividad de Zabbix, consulta parámetros físicos directos en Smart OLT, filtra falsos positivos por mismatch y envía tarjetas HTML enriquecidas a Telegram y mapas interactivos.

Propósito del Sistema
Zabbix detecta caídas de hosts de forma lógica mediante pings o SNMP. Sin embargo, no conoce la topología de fibra óptica (puerto PON, slot, caja NAP o dirección del cliente). Este middleware actúa como puente resolviendo en milisegundos las referencias físicas y geográficas en la base de datos de Smart OLT antes de reportar.

Directorio y Responsabilidad de Archivos

Organización modular del código en el espacio de trabajo:

Entrypoint
src/index.js Carga variables de entorno, monta el servidor Express HTTP en el puerto especificado, acopla el WebSocket Server para transmisiones visuales y programa tareas cron (cada 30 min) para re-sincronizar el caché.
Enrutamiento
src/routes/webhook.js Implementa los controladores REST. Integra el de-bouncer temporal para evitar alertas por cortes breves de energía y los filtros de validación cruzada.
Servicio Smart OLT
src/services/smartOlt.js Interpola con los endpoints API de Smart OLT. Resuelve búsquedas por SN, busca ONUs en cascada en una misma NAP para alertas globales y obtiene logs directos de los estados PON.
Caché y Base de Datos
src/services/cache.js Genera el archivo local nap_cache.json para almacenar coordenadas geográficas de las cajas NAP calculadas de forma ponderada según las ubicaciones de sus clientes.
Servicio Zabbix API
src/services/zabbix.js Cliente JSON-RPC para interactuar con la base de datos de Zabbix. Autentica dinámicamente y expone consultas para barrer todos los incidentes activos bajo demanda.
Servicio Telegram
src/services/telegram.js Wrapper del API de Telegram. Habilita el envío de mensajes HTML nativos y gestiona las solicitudes de respuesta del Bot tanto en modo polling como webhook.
WebSocket Server
src/services/websocket.js Permite conexiones TCP bidireccionales con navegadores web para actualizar el mapa interactivo de cajas NAP de manera inmediata ante cualquier cambio de estado.
Parser de Texto
src/utils/parser.js Módulo central para procesar strings provenientes de Zabbix y Telegram, aislando números de serie, identificando nombres de cajas NAP y normalizando horas a UTC-5.

Esta ilustración representa el flujo lógico cuando se activa una alarma en Zabbix, se contrasta con Smart OLT y se envía la alerta correspondiente:

Ciclo de Vida del Evento

Descripción cronológica de cómo procesa la API una alerta individual enviada por Zabbix:

  1. 1

    Recepción del Payload

    Zabbix envía una petición POST HTTP a /webhook/zabbix conteniendo un objeto JSON con el nombre del evento, la severidad, el estado (PROBLEM u OK) y el texto descriptivo del trigger.

  2. 2

    Extracción del Serial Number (SN) y la Hora

    La API analiza el texto en busca de un número de serie GPON de 12 o 16 caracteres hex. Simultáneamente, extrae la marca de tiempo exacta del inicio de la falla provista por Zabbix o, en su defecto, calcula el instante UTC-5.

  3. 3

    Debouncing (Si aplica a fallas de energía)

    Si el evento es clasificado como pérdida de energía (Power Fail) y su estado es PROBLEM, la API retiene la alerta por 5 minutos (configurable vía POWER_ALERT_DELAY_MINS). Si en ese lapso ingresa un evento OK para el mismo SN, la alerta se cancela evitando spam por micro-cortes.

  4. 4

    Validación y Corroboración Cruzada con Smart OLT

    El middleware busca el SN en Smart OLT. Si el dispositivo no existe en Smart OLT, o si existe una discrepancia lógica de estado (ej: Zabbix dice PROBLEM pero Smart OLT dice Online), el evento se clasifica como mismatch y se aborta el envío del mensaje a Telegram.

  5. 5

    Generación de Reporte y Envío a Telegram / WebSockets

    Si la alerta supera los filtros, se ejecuta un mapeo de la caja NAP correspondiente, se verifica el estado actual de los demás clientes de esa caja para identificar si se trata de un corte individual o un incidente masivo, y se despacha una tarjeta HTML formateada a Telegram. Adicionalmente, se actualiza el panel web vía WebSockets.

Catálogo de Servicios

Detalle de métodos, firmas y responsabilidades de los servicios principales:

Smart OLT API Client (`src/services/smartOlt.js`)

Se encarga de interactuar con la API REST externa expuesta por Smart OLT. Requiere SMARTOLT_SUBDOMAIN y SMARTOLT_API_KEY.

Métodos expuestos:

  • findOnuBySn(sn): Obtiene detalles estáticos de la ONU (Cliente, Dirección, Slot, Puerto, NAP asignada). 
    const onu = await findOnuBySn('HWTC12345678');
  • getOnuStatus(externalId): Consulta en la OLT el estado dinámico actual, potencia de Rx y razón de la última desconexión. 
    const status = await getOnuStatus('12345');
  • findOnusByAddressQuery(query): Devuelve la lista de clientes asociados a una dirección o término de búsqueda (ej. caja NAP). 
    const onus = await findOnusByAddressQuery('NAP-04-A');
  • findOnusByPort(oltId, board, port, fallbackOltName): Retorna las ONUs conectadas al mismo puerto físico para calcular el punto de corte en cascada de fibra.

Zabbix RPC Client (`src/services/zabbix.js`)

Gestiona la consulta del histórico y estado actual de eventos lógicos de Zabbix. Requiere ZABBIX_API_URL y un ZABBIX_API_TOKEN válido.

Métodos expuestos:

  • authenticate(): Negocia un token de sesión JSON-RPC si se utilizan credenciales clásicas de Zabbix.
  • getActiveTriggers(): Llama al método trigger.get filtrando por estado PROBLEM (value: 1) para barrer y consolidar la red.
// Ejemplo de llamada interna JSON-RPC
const response = await fetch(url, {
  method: 'POST',
  body: JSON.stringify({
    jsonrpc: '2.0',
    method: 'trigger.get',
    params: {
      output: ['triggerid', 'description', 'priority', 'lastchange'],
      selectHosts: ['hostid', 'host', 'name'],
      filter: { value: 1, status: 0 },
      monitored: true
    },
    auth: token,
    id: 1
  })
});

API Endpoints

Definiciones HTTP expuestas por el middleware para su integración:

1. Webhook de Eventos Zabbix

Endpoint: POST /webhook/zabbix

Este endpoint es invocado de manera directa por las acciones de alertas de Zabbix ante transiciones PROBLEM u OK.

JSON Payload (Ejemplo):

{
  "event_name": "ONU FHTT8c3a91bf: Loss of Signal",
  "host_name": "OLT-CENTRAL",
  "event_severity": "High",
  "event_status": "PROBLEM",
  "clock": 1722123456
}

Respuestas:

  • 200 OK: Retorna { "status": "success", "sent": true, "sn": "FHTT8C3A91BF", "enriched": true } si se enriqueció y envió correctamente.
  • 200 OK (Ignorado): Retorna { "status": "ignored", "sent": false, "reason": "State mismatch..." } si se bloqueó por corroboración de OLT.
  • 200 OK (Encolado): Retorna { "status": "queued", "message": "Power failure alert queued..." } si aplica de-bounce de energía.

2. Sincronización Manual de Fallas Activas

Endpoint: GET /webhook/zabbix/sync

Realiza un barrido masivo consultando la API de Zabbix para extraer todas las fallas vivas, cruzar sus SNs con Smart OLT y enviar un resumen consolidado a Telegram.

Parámetros Query String:

  • chat_id (opcional): Telegram Chat ID alternativo a reportar.

3. Coordenadas de Cajas NAP

Endpoint: POST /webhook/naps/coordinates

Actualiza la geolocalización de una caja NAP específica en el caché y propaga el cambio vía WebSockets.

JSON Payload (Ejemplo):

{
  "name": "NAP-04-A",
  "latitude": -12.046374,
  "longitude": -77.042793
}

Expresiones Regulares & Normalización

El parser [parser.js](file:///c:/Users/USUARIO/Desktop/api_zaSmaOlt/src/utils/parser.js) normaliza y filtra datos no estructurados:

1. Extracción de Números de Serie

El sistema admite seriales directos de 12 caracteres o cadenas hexadecimales de 16 caracteres (comunes en alertas de red por SNMP traps), convirtiendo los primeros 8 caracteres (identificador del vendedor en ASCII) y concatenando la porción hexadecimal restante:

  • Regex estándar GPON: /\b([A-Z0-9]{4}[0-9A-Fa-f]{8})\b/i
  • Regex hexadecimal (16-char): /\b([0-9A-Fa-f]{16})\b/i (Ej: 4857544338423232 → HWTC38423232)

2. Extracción de Cajas NAP

Localiza identificadores en direcciones o descripciones mediante:

const NAP_REGEX = /(NAP[-_.\s]*\d+(?:[-_.\s]*[A-Z0-9]{1,2})?\b|caja\s+NAP[-_.\s]*\d+\b)/i;

Lógica de Corroboración

La lógica de corroboración previene falsas notificaciones. Compara el estado del evento reportado por Zabbix contra el estado real de la base de datos viva de Smart OLT:

Alerta Zabbix Estado OLT Acción Realizada Razón Técnica
PROBLEM (LOS/Power Fail) Offline ENVIAR ALERTA Ambos sistemas coinciden. Alerta corroborada.
PROBLEM (LOS/Power Fail) Online / Active BLOQUEAR ENVÍO mismatch. El cliente se restableció rápido o fue una falsa alarma de Zabbix.
OK (Recuperación) Online / Active ENVIAR ALERTA Servicio operativo. Se confirma la recuperación del cliente.
OK (Recuperación) Offline BLOQUEAR ENVÍO mismatch. Zabbix infirió recuperación pero la OLT confirma que sigue offline.

Gestión de Fecha/Hora y Huso Horario (UTC-5)

Dado que el servidor middleware puede correr en entornos de nube con marcas de tiempo UTC, se implementa una lógica de conversión manual estricta para garantizar que el reporte en Telegram refleje siempre la hora local de operación de **Bogotá/Quito/Lima (UTC-5)** sin depender de configuraciones regionales del sistema operativo:

export function formatDateTime(date) {
  // Resta exactamente 5 horas en milisegundos
  const offsetMs = -5 * 60 * 60 * 1000;
  const adjusted = new Date(date.getTime() + offsetMs);
  
  const yyyy = adjusted.getUTCFullYear();
  const mm = String(adjusted.getUTCMonth() + 1).padStart(2, '0');
  const dd = String(adjusted.getUTCDate()).padStart(2, '0');
  const hh = String(adjusted.getUTCHours()).padStart(2, '0');
  const min = String(adjusted.getUTCMinutes()).padStart(2, '0');
  const ss = String(adjusted.getUTCSeconds()).padStart(2, '0');
  
  return `${yyyy}-${mm}-${dd} ${hh}:${min}:${ss}`;
}

Configuración de Alertas en Zabbix

Para integrar Zabbix, crea una acción de alerta que envíe un Webhook a la API. Configura el script en el panel de Zabbix (Administration → Media Types) con el siguiente código JavaScript:

try {
    var params = JSON.parse(value),
        req = new HttpRequest(),
        resp;

    req.addHeader('Content-Type': 'application/json');
    resp = req.post('http://tu-middleware-url:3010/webhook/zabbix', JSON.stringify({
        event_name: params.event_name,
        host_name: params.host_name,
        event_severity: params.event_severity,
        event_status: params.event_status,
        clock: params.event_clock
    }));

    if (req.getStatus() !== 200) {
        throw 'Error al enviar webhook';
    }

    return 'OK';
} catch (error) {
    Zabbix.log(3, 'Webhook error: ' + error);
    throw error;
}
